    How it works

    1. Render. Each catalog star in the 20° field becomes a small Gaussian blob on a 1024×1024 sensor, plus background and read noise.
    2. Detect. Pixels 5σ above the background that are the brightest in their 3×3 neighbourhood are stars; a 5×5 brightness-weighted mean finds each centre to about 0.1 pixel (7 arcseconds).
    3. Vote. The angle between two stars doesn't depend on where the camera points. For every pair of dots, the tracker looks up all catalog pairs with nearly the same angle (266,153 pairs, sorted, binary search) and votes for their stars. The right star collects a vote from almost every pair it is in; wrong ones only collect coincidences.
    4. Check. Names that disagree with the others (fake stars, unlucky votes) are dropped.
    5. Solve. Wahba's problem by SVD gives the rotation that best maps catalog directions onto camera directions.
    6. Verify. With that attitude, at least 4 dots must land within 25″ of catalog stars, or the answer is "no solution". It never guesses.

    The live tab runs the project's actual Python code (tracker/) in your browser through Pyodide. The large validation campaign and the GPU benchmark ran on an NVIDIA Tesla T4 with hand-written CUDA kernels; a web page cannot use a GPU that way, so those numbers are stored results (Results tab).
